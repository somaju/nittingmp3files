# App delivery

## Decisions

- 앱은 웹서비스로 배포한다. 사용자는 주소로 접속해 브라우저에서 쓴다.
- 음원 파일은 서버에 올리지 않는다. 사용자의 브라우저가 입력 폴더를 읽고 출력 폴더에 직접 쓴다. 폴더는 브라우저의 폴더 선택창으로 고르고, 파일 이름 변경과 태그 쓰기도 브라우저에서 한다.
- 서버는 화면을 제공하고 곡 정보 검색 요청을 대신 보내는 일만 한다. 서버에 사용자의 음원 파일을 보내거나 저장하지 않는다.
- 브라우저의 폴더 접근 기능을 지원하는 브라우저(Chrome, Edge 같은 Chromium 계열)에서만 쓸 수 있다. Safari와 Firefox는 지원하지 않는다.
- macOS와 Windows 모두에서 같은 방식으로 동작해야 한다.

## Boundaries

- 이 결정은 앱이 사용자에게 전달되는 형태와 파일을 다루는 위치를 정한다. 곡 정보를 어디서 찾는지는 정하지 않는다.
- 브라우저는 운영체제의 파일 관리자를 열거나 폴더의 실제 경로를 알려 주지 않는다. 이를 전제로 화면을 정한다.

## Why

사용자가 npm 배포 대신 웹서비스로 배포하기로 바꿨다. 웹서비스의 서버는 사용자 컴퓨터의 폴더를 읽을 수 없다. 음원 파일(100곡이면 수백 MB)을 서버로 올렸다가 다시 내려받는 방식은 시간과 저장 비용이 들고 출력 폴더를 직접 지정할 수 없다. 브라우저가 폴더를 직접 읽고 쓰면 파일이 서버를 거치지 않아 "원본은 그대로 두고 지정한 출력 폴더에 결과를 만든다"는 제품 경계를 그대로 지킬 수 있다.

## Reconsider when

- Safari나 Firefox 사용자를 지원해야 할 때
- 브라우저의 폴더 접근 기능이 두 운영체제의 Chromium 브라우저 중 하나에서 안정적으로 동작하지 않을 때
- 사용자가 설치 파일이나 `npx` 같은 로컬 실행 방식을 다시 원할 때

## Still-rejected alternatives

- 파일을 서버에 올리고 결과를 내려받기 — 업로드와 다운로드 시간, 서버 저장과 삭제 정책이 필요하고 출력 폴더를 직접 지정할 수 없다. 모든 브라우저 지원이 필요해지면 다시 검토한다.
- `npx`로 실행하는 로컬 웹 앱 — 사용자가 배포 방식을 웹서비스로 바꾸면서 폐기했다.
- Electron 같은 데스크톱 앱 — 운영체제별 설치 파일 구성이 무겁다. 설치 파일 배포가 필요해지면 다시 검토한다.
