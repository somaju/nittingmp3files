# MP3 정리 앱

폴더를 고르면 안에 있는 mp3의 파일명을 `노래이름 - 가수이름.mp3`로 통일하고 빈 태그를 채워 출력 폴더에 정리해 주는 앱의 첫 번째 완성 범위.

## Sources

- [PRODUCT.md](../../../PRODUCT.md) — 앱 전체의 사용자, 문제, 약속하는 변화, 핵심 흐름, 경계. 이 spec은 그중 이번 범위에 적용되는 제약만 가져온다.
- [prototype.html](prototype.html) — 승인된 화면 3개(폴더 선택, 변환 진행, 결과 확인)의 구조, 상태, 동작의 기준. 곡 데이터와 가사는 모두 더미다.
- [GLOSSARY.md](../../../GLOSSARY.md) — 입력 폴더, 출력 폴더, 정리, 완료, 확인 필요, 처리 못함, 처리하지 못한 목록, 후보, 태그 충돌의 정의.
- [docs/decisions/app-delivery.md](../../decisions/app-delivery.md) — 웹서비스 배포, 음원 파일은 서버에 올리지 않고 브라우저가 폴더를 읽고 씀, Chromium 계열 브라우저 한정. 폴더 선택 방식은 이 계약을 따른다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 화면은 shadcn/ui 구성과 semantic token으로 만든다. 프로토타입의 화면 구조를 이 계약에 맞춰 구현한다.

## 사용자에게 보이는 결과

1. 사용자는 웹서비스에 접속해 브라우저의 폴더 선택창으로 폴더를 고른다.
2. 앱은 폴더 안의 mp3를 분석해 곡을 찾고, 진행 상황을 보여 주며 정리한다.
3. 정리가 끝나면 완료 알림이 뜨고, 사용자는 결과 확인 화면에서 곡마다 파일명, 앨범아트, 태그, 가사를 보고 재생해 볼 수 있다.
4. 앱이 확정하지 못한 곡은 이유와 함께 보여 주고 사용자가 선택하거나 입력해서 마무리한다.

## 범위

- 입력 폴더와 출력 폴더 선택: 시작 위치 목록(음악, 다운로드 등)과 브라우저의 폴더 선택창.
- 폴더 안 mp3 분석, 곡 검색, 파일명 변경, 빈 태그 채우기, 출력 폴더에 새 파일 생성.
- 채우는 태그: 제목, 가수, 앨범, 장르, 출시년도, 앨범아트, 가사.
- 변환 진행 화면과 변환 완료 알림.
- 결과 확인 화면: 상태별 곡 목록과 곡 상세, 재생, 후보 선택, 태그 충돌 선택, 처리하지 못한 곡의 제목과 가수 입력과 재검색.
- macOS에서 실행되며 Windows에서도 같은 동작이 되도록 만든다.

## 범위 밖

- 처리 전 미리보기 단계. 원본이 그대로 남으므로 처리 후에 확인한다.
- 음원 지문 인식으로 곡을 찾는 기능. 곡은 파일명과 기존 태그의 글자로만 찾는다.
- 시간 정보가 있는 가사(줄 단위 동기화).
- 입력 폴더의 하위 폴더 탐색, mp3 이외 형식(처음 범위에서는 정하지 않는다. 아래 보류 참고).
- 사용자 계정, 로그인, 클라우드 동기화. 앱은 혼자 쓰는 개인용이다.

## 인수 기준

폴더 선택
- 정리할 폴더를 고르기 전에는 "변환 시작"을 누를 수 없다.
- 음악, 다운로드, 바탕화면 같은 시작 위치를 한 번 눌러 브라우저의 폴더 선택창을 그 위치에서 열 수 있다. 고른 폴더에 mp3가 없으면 알리고 시작할 수 없다.
- 폴더 선택창에서 입력 폴더와 출력 폴더를 고른다. 출력 폴더에는 사용자가 쓰기를 허용해야 한다.
- 출력 폴더는 사용자가 직접 고른다. 브라우저는 선택한 폴더 옆에 새 폴더를 만들 수 없으므로 기본값을 두지 않고, 정리할 폴더와 같은 폴더는 고를 수 없다.
- 입력 폴더 안의 어떤 파일도 변환 중이나 변환 후에 수정되거나 삭제되거나 이동되지 않는다.

변환
- 변환 중에는 처리한 곡 수와 전체 곡 수, 완료/확인 필요/처리 못함/남은 곡 수, 방금 처리한 곡이 갱신되어 보인다.
- 곡 하나가 확인 필요나 처리 못함이어도 나머지 곡의 처리는 멈추지 않는다.
- 한 번에 약 100곡을 처리할 수 있다.
- 사용자가 한글로 적은 제목과 한국 가수의 이름은 서비스가 영어 표기를 돌려줘도 파일명과 태그에 한글 그대로 쓴다. 외국 가수의 이름은 한글로 적었어도 서비스의 영문 이름으로 바꾼다(사용자 결정). 한국 가수인지는 서비스가 돌려준 장르(K-Pop 등)로 판단하고, 장르를 알 수 없으면 한글을 유지한다. 가사는 서비스의 원래 표기로도 찾아본다.
- 완료한 곡의 파일 안 제목 태그는 `노래이름 - 가수이름`이고 파일명은 그 제목과 같다(`노래이름 - 가수이름.mp3`). 가수 이름은 제목 안에 한 번만 들어가며, 가수는 가수 태그에 따로 들어간다(사용자 결정). 운영체제가 파일명에 허용하지 않는 문자는 안전한 문자로 바꾸거나 제거한다.
- 출력 폴더에 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 그 곡은 건너뛴다(사용자 결정). 건너뛴 곡은 결과 확인에서 "이미 있음"으로 보이고 완료 분류에 센다. 직접 편집과 후보 선택으로 저장할 때도 같다.
- 완료한 곡에는 제목, 가수, 앨범, 장르, 출시년도, 앨범아트, 가사 중 찾은 정보가 태그로 들어간다.
- 기존 태그에 값이 있고 검색 결과와 같으면 그대로 두고, 비어 있으면 채운다. 값이 서로 다르면 태그 충돌로 사용자 선택에 맡긴다.
- 곡 정보는 iTunes Search와 MusicBrainz에서 찾는다. 곡이 하나로 정해지면 자동으로 적용하고, 후보가 여러 개이거나 정해지지 않으면 확인 필요로 둔다.
- 기존 태그의 제목에 가수 이름이 섞여 있거나(예: `After School - Weeekly`) 괄호 설명이 붙어 있으면, 정리한 제목으로 검색하고 정리한 제목이 찾은 제목과 같으면 충돌로 보지 않고 깨끗한 제목으로 바꾼다. 실제 폴더 실행 로그에서 확인한 문제다.
- 제목 앞이나 뒤에 가수 이름이 이미 붙어 있으면(예: `Christina Perri A Thousand Years`) 가수 이름은 한 번만 남기고 제목에서 지운다(사용자 결정). 지운 뒤 두 글자 이상 남을 때만 지운다. 가수가 둘 이상이면 한 명의 이름만 붙어 있어도 지운다.
- 앱을 실행했을 때 이어서 처리할 변환이나 처리하지 못한 목록이 남아 있으면 팝업이 뜬다. 팝업에는 남은 곡 수가 보이고, "이어서 처리하기", "처리하지 못한 곡 보기", "나중에" 중 하나를 고를 수 있다. 남은 것이 없으면 팝업은 뜨지 않는다.
- 처리하지 못한 곡은 앱을 닫았다가 다시 실행해도 처리하지 못한 목록에 계속 남는다. 사용자가 마무리한 곡만 목록에서 사라진다.
- 변환이 중간에 멈추면(앱 종료, 컴퓨터 종료, 오류 등) 다시 실행했을 때 이미 끝낸 곡은 다시 처리하지 않고, 멈춘 곡부터 이어서 처리한다. 이어서 처리해도 출력 폴더에 같은 곡의 파일이 중복으로 만들어지지 않는다.
- 변환이 끝나면 "변환 완료" 알림이 뜬다. 알림에는 출력 폴더 이름과 완료, 확인 필요, 처리 못함의 곡 수가 보인다. 브라우저는 파일 관리자를 열 수 없으므로 출력 폴더를 자동으로 열지 않는다. 사용자가 확인한 결정이다.

결과 확인
- 곡 목록은 전체, 완료, 확인 필요, 처리 못함으로 거를 수 있고 각 분류의 곡 수가 보인다. 각 곡 행에는 앨범아트, 새 파일명, 상태가 보인다.
- 완료한 곡의 상세에는 앨범아트, 파일명, 태그, 원본 파일명, 재생 버튼, 가사가 보인다.
- 후보가 여러 개인 확인 필요 곡은 후보를 나란히 보여 주고, 하나를 고르면 그 곡만 출력 폴더에 만들어지고 완료로 바뀐다.
- 태그 충돌인 곡은 기존 값과 검색 값을 항목별로 보여 주고, 다른 항목을 모두 고른 뒤에만 적용할 수 있다. 비어 있던 항목은 자동으로 채워져 보인다.
- 후보가 여러 개인 확인 필요 곡의 후보 아래에도 "맞는 곡이 없습니다. 제목이나 가수를 입력해 다시 검색" 입력칸이 있어서, 후보가 모두 틀렸을 때 바로 다시 검색할 수 있다.
- 확인 필요 곡(후보 선택, 태그 충돌 모두)과 처리 못함 곡에는 "직접 편집" 모드가 있다. 제목, 가수, 앨범, 장르, 출시년도, 가사를 사용자가 손으로 고치고, 저장할 파일명을 미리 보며 "이대로 저장"하면 입력한 값 그대로 파일명과 태그를 만든다. 제목과 가수는 꼭 있어야 하고, 앨범아트와 가사는 파일에 있으면 그것을, 없으면 찾은 것을 쓴다(사용자 결정).
- 처리 못함 곡은 이유를 설명하고 재생할 수 있다. 파일명이 깨졌거나 검색 결과가 없으면 제목을, 가수를 찾지 못했으면 가수를 입력해 다시 시도한다.
- 입력하지 않으면 그 곡은 출력 폴더에 만들어지지 않고 처리하지 못한 목록에 남는다.
- 확인 필요이거나 처리 못함인 곡은 사용자가 마무리하기 전까지 출력 폴더에 만들어지지 않는다.
- "다른 폴더 정리"로 이동할 수 있다.

화면
- 좁은 화면에서는 목록과 상세가 위아래로 쌓이고, 곡을 고르면 상세로 이동한다. 가로 스크롤이 생기지 않는다.
- 밝은 테마와 어두운 테마를 지원한다.

## 확정된 제약과 근거

- 앱은 웹서비스로 배포하고, 음원 파일은 서버에 올리지 않으며 브라우저가 입력 폴더를 읽고 출력 폴더에 쓴다. 근거는 [app-delivery](../../decisions/app-delivery.md)를 따른다.
- 곡은 파일명과 기존 태그에서 만든 검색어로 찾는다. 파일명이 깨진 곡은 처리하지 못한 곡으로 둔다는 PRODUCT.md의 경계와 맞기 때문이다.
- 사용자에게 토큰이나 계정 같은 설정을 요구하지 않고, 앱이 인터넷을 검색해 곡 정보를 직접 찾아 태그에 넣는다.
- 사용자가 API 키나 토큰을 입력하는 방식은 쓰지 않는다. 곡 정보는 키 없이 쓸 수 있는 서비스로 확보한다. 근거는 혼자 쓰는 앱에 설정을 요구하지 않기 위해서다.
- 곡 확정과 앨범명, 장르, 출시년도, 앨범아트는 iTunes Search와 MusicBrainz에서 얻고, 가사는 LRCLIB에서 얻는다. 구글 검색은 쓰지 않는다. 공식 API는 키가 필요하고 검색 결과 페이지는 자동 조회가 허용되지 않기 때문이다(아래 보류 참고). Deezer는 같은 질의에서 다른 곡을 먼저 돌려주어 제외한다.
- 처리하지 못한 목록과 변환 진행 상태는 앱을 닫아도 남아 있어야 한다. 근거는 100곡을 한 번에 처리하다 중간에 멈춰도 다시 처음부터 하지 않기 위해서다.
- 확인 필요 곡은 사용자가 고르기 전에 출력 폴더에 쓰지 않는다. 틀린 정보가 조용히 들어가는 것을 막는다.
- 틀려 보이는 기존 태그를 앱이 임의로 바꾸지 않는다. PRODUCT.md의 경계다.

## 가정 (바꿀 수 있는 기본값)

- 가사는 줄 단위 시간 정보가 없는 일반 텍스트로 넣는다. 시간 동기 가사는 기기마다 표시 지원이 달라서 쓰지 않는다.
- 처리 전 미리보기 단계는 두지 않는다.
- 변환 완료 시점의 완료, 확인 필요, 처리 못함 곡 수는 알림과 결과 확인 화면에서 같은 숫자로 보인다.
- 출력 폴더는 변환 시작 전에 정하고, 변환 중에는 바꾸지 않는다.
- 앨범아트는 가능한 한 큰 크기로 태그에 넣는다.

## 보류

- **곡이 "하나로 정해졌다"고 보는 기준.** 제목과 가수가 어느 정도까지 같아야 곡이 하나로 정해졌다고 보는지, 두 서비스의 결과가 서로 다를 때 어느 쪽을 믿는지는 정하지 않았다. 임시로 정규화한 제목과 가수가 모두 같은 후보가 하나뿐일 때만 자동 적용하고, 나머지는 확인 필요로 둔다.
- **구글 검색을 쓰지 않는 근거.** 사용자가 직접 확인한 결과다. 구글 공식 검색 API는 키 없이 호출하면 403(PERMISSION_DENIED, "Method doesn't allow unregistered callers")으로 거부된다. 구글 robots.txt는 `Disallow: /search`로 검색 결과 페이지의 자동 조회를 허용하지 않는다. 같은 질의("IU Good Day")로 키 없이 응답한 서비스는 다음과 같다. LRCLIB는 제목, 가수, 앨범, 일반 텍스트 가사를 돌려주었다. iTunes Search는 가수, 앨범, 제목을 돌려주었고 장르, 출시일, 앨범아트 필드는 출력이 잘려 확인하지 못했다. MusicBrainz는 점수 100의 일치 결과를 돌려주었고 장르, 출시년도, 앨범아트는 확인하지 못했다. Deezer는 다른 곡을 먼저 돌려주었다.
- **서비스별로 어떤 정보를 맡길지.** iTunes Search와 MusicBrainz 중 어느 쪽에서 장르, 출시년도, 앨범아트를 가져오고, 한쪽에 없을 때 다른 쪽을 쓰는 순서를 정하지 않았다. 가사는 LRCLIB로 정했다. 구현 전에 실제 곡으로 각 필드가 오는지 확인하고 확정한다.
- **재개 팝업의 세부 문구와 동작.** 팝업으로 구성하는 것은 정해졌다(인수 기준 참고). 문구, 버튼 배치, 남은 곡 수 표기는 구현 때 화면 구성 계약에 맞춰 정한다. 프로토타입에는 없다.
- **서버의 역할과 호스팅 위치.** 서버는 화면 제공과 곡 정보 검색 요청 전달만 한다고 정했다. 브라우저에서 서비스를 직접 호출할 수 있는지(교차 출처 허용, 서비스가 요구하는 식별 정보)는 확인하지 못했다. 서비스를 어디에 호스팅할지, 여러 사람이 쓰는지는 정하지 않았다. 임시로 계정 없이 쓰고 한 사용자의 요청이 서버를 거치게 한다.
- **재개에 필요한 폴더 권한과 저장 위치.** 임시로 변환 진행 상태와 처리하지 못한 목록은 브라우저 저장소에 저장하고, 다시 열면 브라우저가 폴더 접근 권한을 다시 물을 수 있다. 다른 브라우저나 기기에서는 이어지지 않는다.
- **변환 중 사용자가 직접 취소하는 기능.** 논의하지 않았다. 임시로 취소 버튼은 두지 않고, 앱을 닫으면 중단으로 보고 다음 실행 때 이어서 처리한다.
- **입력 폴더의 하위 폴더와 mp3 이외 형식.** 논의하지 않았다. 임시로 입력 폴더 바로 아래의 mp3만 대상으로 한다.
- **이미 정리된 폴더를 다시 정리할 때의 동작.** 논의하지 않았다. 임시로 같은 이름의 파일이 출력 폴더에 이미 있으면 그 곡을 건너뛰므로, 같은 폴더를 다시 정리해도 이미 만든 곡은 다시 만들지 않는다.
- **한글과 영문 곡 이름을 모두 찾는 방법.** 한글 가수명과 영문 가수명이 섞인 곡을 어떻게 찾을지 정하지 않았다.

## 남은 위험

- iTunes Search와 MusicBrainz가 한국 곡이나 YouTube에서 받은 곡을 잘 찾지 못할 수 있다. 이런 곡이 많으면 확인 필요와 처리 못함이 많아져 사용자 수작업이 늘어난다. 사용자가 확인한 결과: iTunes Search는 "아이유 좋은날"에 영어 표기 곡(Good Day / IU)을 돌려주었다. 한글로 적힌 파일명은 영어로 등록된 곡과 글자가 달라 자동 확정되지 않고 확인 필요로 남으며, 이때 맞는 후보는 목록에 보인다. "BTS Dynamite"처럼 가수와 제목이 이어 적힌 이름은 확정된다. 등록되지 않은 곡(예: 지어낸 곡 이름)은 관련 없는 후보가 나오므로 확인 필요에서 사용자가 건너뛰어야 한다. 실제 폴더의 곡 7개로 확인한 결과(검색어를 iTunes에 직접 조회, 제목-가수 순서 이름): 자동 확정 4곡, 확인 필요 2곡(맞는 후보가 목록에 있음), 못 찾음 1곡이다. 가수 표기만 한글과 영문으로 다른 경우(예: 사라 브라이트만과 Sarah Brightman)는 제목이 같고 그런 곡이 하나일 때 확정한다. 서비스가 제목이나 가수를 영어 표기(예: 가족사진은 Family Portrait, 전인권은 Jeon Inkwon)로 돌려줘도 사용자가 한글로 적은 이름은 그대로 유지한다(사용자 결정). 서비스 값은 앨범, 장르, 출시년도, 앨범아트에만 쓴다. 쉼표로 가수가 둘인 이름(Christopher, 청하)은 전체 이름으로는 iTunes가 결과를 주지 않았다. 가수가 둘 이상이면(쉼표, &, feat., /, and, x 등으로 구분) 전체 이름과 가수 한 명씩 모두 검색해 후보를 합치고, 가수 한 명이 후보의 가수 이름에 들어 있으면 같은 가수로 본다(사용자 결정).
- 같은 곡도 원곡, 리마스터, 모음집에 따라 앨범, 장르, 출시년도가 다를 수 있다. 태그에 들어갈 값이 사용자가 기대하는 값과 다를 수 있다.
- 키 없이 쓰는 서비스는 요청 횟수 제한이나 이용 규칙(예: MusicBrainz는 요청 간격 제한과 식별 가능한 User-Agent 요구)이 있는 것으로 알고 있으나 확인하지 못했다. 100곡을 한 번에 처리하는 시간이 길어질 수 있다.
- iTunes Search는 장르, 출시일, 앨범아트(100x100bb 주소, 앱이 600x600bb로 바꿔 쓴다)를 실제로 돌려주는 것을 사용자가 "IU Good Day" 질의로 확인했다. MusicBrainz의 앨범아트(Cover Art Archive)와 한국 곡, YouTube에서 받은 곡의 확정 비율은 아직 확인하지 못했다.
- 서버가 모든 사용자의 곡 정보 검색을 대신 보내면 서비스의 요청 횟수 제한(예: MusicBrainz의 초당 요청 제한)을 쉽게 넘길 수 있다. 사용자가 늘면 처리 시간이 길어지거나 실패가 늘어난다.
- 브라우저 저장소가 지워지면 처리하지 못한 목록과 진행 상태를 잃는다.
- 브라우저가 100곡의 음원을 읽고 태그를 쓰는 동안 탭이 닫히거나 메모리가 부족해 멈출 수 있다. 태그 쓰기를 브라우저에서 할 방법(앨범아트, 가사 포함)은 확인하지 못했다.
- 사용자가 폴더 접근 권한을 거부하거나, 쓰기를 허용하지 않으면 출력 폴더에 쓸 수 없다.
- 처리하지 못한 목록과 진행 상태를 저장하는 위치에서 파일이 지워지거나 입력 폴더의 파일이 바뀌면, 이어서 처리할 때 어긋날 수 있다.
- 공개 서비스의 요청 제한이나 응답 변경으로 100곡을 한 번에 처리하는 시간이 길어지거나 일부 곡이 실패할 수 있다.
- 가사는 서비스에 없는 곡이 많을 수 있다. 가사가 없는 곡을 완료로 볼지 정하지 않았다. 임시로 가사가 없어도 나머지 정보가 채워지면 완료로 보고 가사만 비워 둔다.
- 태그에 넣은 앨범아트와 가사가 아이폰, 스마트워치, 이어폰에서 실제로 표시되는지는 확인하지 못했다.
- Safari와 Firefox는 브라우저의 폴더 접근 기능을 지원하지 않아 이용할 수 없다. macOS와 Windows의 Chromium 브라우저에서 같은 동작인지는 확인하지 못했다.
- 파일명이 깨진 곡을 자동으로 복구하지 않고 사용자 입력에 맡기므로, 이런 곡이 많은 폴더에서는 사용자 수작업이 많이 남는다.
